# SteamCardToolkit

Steam 集换式卡牌批量上架油猴脚本。

直接调用 Steam 自身的库存与市场接口完成批量上架，**不依赖页面 DOM**，
因此不会因为 Steam 改版而失效。

---

## 功能

- **一次拉取全部社区物品** —— 卡牌、闪卡、表情、背景、宝石一次读全，不需要翻页
- **按游戏批量取价** —— 走市场搜索接口，全量查价不再受逐张查价的限流影响
- **三种上架规则** —— 底价上架 / 固定附加 / 百分比附加，自动完成手续费反推
- **普通卡 / 闪卡分开筛选** —— 手动勾选上架范围，不做默认批量
- **「仅重复」模式** —— 每组卡保留指定张数，只卖多余的
- **库存页和市场页都能用** —— 浏览市场时顺手清一下库存
- **面板可拖动、可折叠成页边小标签** —— 位置和折叠状态会被记住

## 使用

1. 打开自己的 Steam 库存页（`steamcommunity.com/id/<你的ID>/inventory`）
   或任意市场页（`steamcommunity.com/market/`）
2. 右上角出现面板，**脚本会自动读取一次库存**（也可以随时点「刷新库存」重读）
3. 点 **查询底价**，等列表显示出每张卡的挂出价与「到手」金额
   （查询过程可随时点同一个按钮停止）
4. 按需筛选（普通卡 / 闪卡 / 全部），勾选要卖的卡
5. 点 **批量上架选中项**
6. **打开 Steam 手机 App，在「确认」页面批量勾选确认**

> 第 6 步不能省略。没有确认的上架不会生效。

### 勾选与批量选择

- 勾选一张卡会**立刻为它查一次价**，约一秒出结果
- 一张卡有多个重复时，**整组一起勾选** —— 勾一个 `X3` 的分组等于勾 3 张。
  界面刻意不支持「一组里只选一半」
- 四个批量按钮：`全选` / `清空` / `反选` / `底价`
  - `底价` 是**只追加勾选那些已经查到价格**的卡，不会取消你已有的选择。
    想反过来筛选，先点 `清空` 再点它

### 「仅重复」模式

勾上后每张卡**保留指定张数，只卖多余的**；没有多余可卖的卡会从列表里直接隐藏。

例如某张卡有 6 张、保留 4 张，列表里显示 `X2` —— 徽标给的是**要卖几张**，
不是库存总数。可以据此只清理重复卡，不动你的收藏。

它和上方的筛选是两个独立维度：筛选决定**看哪些**，「仅重复」决定**每组卖几张**。

### 面板操作

拖动标题栏可移动面板；点右侧的 `—` 收成贴边小标签，点 `+` 展开。
折叠状态下整个标签都可点击，标签会被吸附到最近的屏幕边缘。
位置与折叠状态会写进 localStorage，刷新页面后保持。

## 上架规则

面板的「上架规则」决定挂出价比市场最低价高多少：

| 规则 | 含义 |
|---|---|
| **底价上架** | 挂出价 = 市场最低价（默认） |
| **固定附加** | 挂出价 = 市场最低价 + N 元 |
| **百分比附加** | 挂出价 = 市场最低价 × (1 + N%) |

这里的附加是加在**买家支付价**（你在市场上看到的那个价）上的。
列表里的「到手」会随规则实时重算，方便你按实际收益决定挂多少。

> 想挂得比最低价高，就要接受可能卖得慢 —— 排在别人后面而已，不会卖亏。

## 重要说明

### 手机令牌是硬约束

如果你的账号启用了 Steam 手机令牌，上架接口只能「发起」请求，
真正生效必须在手机 App 里确认。脚本无法绕过这一步（绕过需要你的令牌密钥，
那不该由脚本持有）。

好消息是手机确认页**支持批量勾选**，所以正确用法是：
脚本一次性发起若干笔 → 到手机上一次性全部确认。

脚本一次最多发起多少笔由内部的「每批上限」控制，默认 30 笔，发满即停 ——
这样可以避免一次堆出上百条待确认，把手机上的确认列表变成负担。
需要调整这个值的话，改脚本里的 `CONFIG.SELL_BATCH_SIZE`（设为 0 表示不限制）。

### 手续费会吃掉低价卡的大部分收益

这是最容易误判的地方。Steam 的各项费用都有最低值兜底，
所以价格越低的卡，手续费占比越夸张：

| 市场最低价 | 你实际到手 | 手续费 |
|---|---|---|
| ¥0.21 | **¥0.07** | ¥0.14 |
| ¥0.28 | ¥0.14 | ¥0.14 |
| ¥0.50 | ¥0.36 | ¥0.14 |
| ¥1.00 | ¥0.85 | ¥0.15 |

¥0.21 的卡卖出去，**三分之二被手续费拿走**。

所以面板列表里同时显示「挂出价」和「到手」两个数字 —— 请按「到手」判断值不值得卖。

### 定价机制

Steam 的上架接口接收的参数是**卖家实收金额**，不是买家支付价。
脚本的定价链路是：

```
市场最低价（买家支付）
   └─ 按规则上浮 ─→ 目标挂出价（买家支付）
        └─ 反推 ─→ 卖家实收  ← 这个值提交给上架接口
```

反推用的是 Steam 自身的费用计算函数，脚本内另有一份等价实现作为兜底，
两者已逐点对拍验证一致。

### 查询状态怎么读

列表价格栏可能出现几种状态，含义不同：

| 显示 | 含义 |
|---|---|
| `查询中…` | 排队等待中 |
| `¥1.20` + `到手 ¥0.85` | 已查到价格 |
| `无挂单` | 市场上确实没人卖这张卡 |
| `限流` | 被 Steam 限流，**不是**「没人卖」，稍后可重试 |
| `失败` | 请求出错，稍后可重试 |
| `—` | 还没查过 |

「限流」和「无挂单」被刻意分开显示 —— 把限流误读成「这卡不值钱」会做出错误的售卖决策。

### 限速

脚本对市场接口做了串行限速（查价 1.5 秒/次、上架 1.2 秒/次）与结果缓存。
批量操作会慢，但这是刻意的 —— 高频请求有触发 Steam 风控的风险，
被封禁的代价远大于多等几分钟。

价格结果会缓存 2 小时，重开页面可直接复用，不必重新等一轮。
